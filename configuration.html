01 / LOCAL SETUP

Launch your personal workspace.

Use the repository instructions to install the Python dependencies and Ollama. Choose the optional document, vision and speech packages you need, then open the dashboard:

Start_Nova.cmd --web-dashboard

Free Mode is selected on startup. The dashboard opens locally; keep the terminal running.

02 / OWNER ACCOUNT

Create once. Sign in next time.

The first visit shows Create your Nova account. Enter an email identifier and a unique password of 12–128 characters. On later visits, use the same account. Restarting Nova does not delete it.

Passwords use salted hashes. Sign out revokes the session. Email verification, password reset, MFA and public multi-user accounts are not implemented.

03 / MODEL CONNECTIONS

Choose where Nova thinks.

Use local Ollama

  1. Install Ollama and download a chat model.
  2. Open Local health and Installed models to inspect the configuration.
  3. Select a local model in AI providers.
  4. Try a short question and verify the response.

Local processing has no provider API bill but uses your computer's CPU/RAM. Vision and speech have their own models and dependencies.

Connect a provider explicitly

  1. Obtain your own provider key and check its quota and pricing.
  2. Open Configuration & credentials; save the key in its registered field.
  3. Select Paid Mode and acknowledge possible billing.
  4. Open AI providers, select the provider and model, set limits, then review and approve the change.

Text adapters: OpenAI, Claude, Gemini, Groq and OpenRouter. Cloud vision is not implemented. Strict model privacy blocks cloud inference/catalogs; Guarded applies best-effort redaction. Request/token caps are not a monetary budget.

05 / MOBILE & HOSTING

A mobile foundation, not a public server.

The web app includes standalone installation assets, icons and responsive screens. Android installation and iPhone Add to Home Screen require a reachable secure deployment and device testing.

Keep source code on GitHub. Host the Python backend separately with HTTPS and a reviewed remote identity flow. Public use additionally needs tenant isolation. Do not expose the current loopback handler directly.

Never commit API keys, passwords, account records, documents or private backup archives.

FIRST-RUN CHECKLIST

From installation to a checked result.

  1. Install only what you need.

    Python runs Nova. Ollama provides local AI. Optional requirements add desktop, speech and document support; model downloads are separate.

  2. Launch and create the owner account.

    Use the web-dashboard launcher, register once and keep your credentials private. The current account system is for a personal owner.

  3. Confirm Free Mode and local health.

    Check model names, package availability and a short real response. Downloaded files alone do not prove a working model.

  4. Try a local task or demo website.

    Create a small item and inspect it. This confirms the interface and file/task workflow before optional services are added.

  5. Connect optional services individually.

    Enter each service's credentials in the appropriate form. Review permissions, provider limits and a small test result before relying on it.

CONFIGURATION QUESTIONS

Keep setup understandable.

Where should I enter email credentials?

Use Email setup in the application. Enter the provider's SMTP/IMAP settings and an app password when required. The owner-login password does not configure your email provider.

Will a provider error switch to another paid service?

Nova does not silently fall back to another provider. Inspect the error and choose your intended connection explicitly. Request and token limits are not a spending guarantee.

How do I connect MCP?

Export Nova's read-only MCP configuration and configure a compatible client. Start the client, confirm the tools it exposes and test a non-sensitive workspace read. Client compatibility still needs live verification.

How do I safely back up records?

Use Nova's backup command, check the archive, and store it privately. Record backups omit models and document files. Restore replaces supported records and requires approval.

Can GitHub host the whole AI?

GitHub can store the source, and static hosting can serve this guide. Nova's Python backend, local models, protected records and remote identity need a separate reviewed deployment.

For detailed implementation status, open the repository's NOVA_PENDING_STATUS.md and USER_ACCEPTANCE_TESTS.md.
