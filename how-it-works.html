HOW NOVA WORKS

From an idea
to a reviewed action.

The dashboard, command interface and voice features use Nova's local tools. Every response should distinguish a proposal from a completed action.

01

Open your workspace

Start the web dashboard on your laptop. Create the personal owner account once, then sign in on future visits. The launcher also supplies a session key.

02

Ask or choose a tool

Type a request, use a slash command or select a dashboard control. Voice input needs an available microphone and speech model.

03

Review sensitive actions

Clipboard writes, deletion, external services and other reviewed operations display an approval request. Approve the exact request or cancel it; requests expire after two minutes.

04

Check the result

Nova reports the tool result or error. Read back the created file, inspect the task list or review the action audit to verify the outcome. A dispatched desktop input does not prove the target app accepted it.

WHERE THINGS LIVE

Your computer

Local models, files, tasks and owner account. Free Mode keeps model routing local. The server must remain running for reminders and dashboard access.

Optional external services

Cloud model requests require configuration and explicit selection. Guarded mode redacts known credentials and selected patterns; it cannot detect every private detail.

What about your phone?

Mobile web-app assets and a responsive login screen are included. The current server is laptop-loopback only. Secure HTTPS deployment and real Android/iPhone tests are still required; GitHub Pages hosts this guide, not Nova's Python backend.

EVERYDAY EXAMPLES

Start with a small, verifiable task.

Create a task

/task Review the project

Open Tasks to inspect the new record. Complete it when the work is finished.

Inspect local health

/doctor

Check configured models and dependencies. Installation does not confirm successful loading or recognition.

Read your file

/tool read_text_file {"path":"notes.txt"}

Place the file inside Nova's Documents workspace. Requests outside it are rejected.

Ask about an image

/vision photo.png | Describe this image.

Requires an installed local vision model and a supported image in the workspace.

WHEN SOMETHING FAILS

Use the result to find the next step.

Model unavailable or connection failed

Check Local health, confirm Ollama is running and verify the exact model name. Try a short chat before a large document request.

File does not exist

Search the Documents workspace and copy the exact filename, including its extension. Windows may hide extensions and create names such as report.docx.docx.

Approval expired

Submit a new request, review its current arguments and approve it within two minutes. An expired token cannot be reused.

Generated code needs fixes

Read the saved files and test them in an appropriate development environment. Generation is not a guarantee of correct or secure production code.
